# Добавление контента через Codex

Сайт только показывает локальные данные. Анализ видео и подготовка иллюстраций выполняются отдельно, в сессии Codex. Не добавляйте AI/API-обработку в приложение.

## Одно упражнение

1. Проверьте идентификацию по достоверному исходному материалу. Сначала найдите возможные совпадения по русскому/английскому названию и алиасам. Сходство названий не означает идентичность техники. Не объединяйте записи автоматически.
2. Добавьте утверждённый оригинал изображения в `public/images/`. Не перерисовывайте карточку без запроса. Стиль Exercise Card v1 задаётся утверждённой карточкой приседа; не добавляйте отдельную шкалу фаз и повторяющийся текст с картинки в UI.
3. Добавьте запись в `src/data/exercises.json`:

```json
{
  "id": "ex-stable-id",
  "slug": "readable-stable-slug",
  "nameRu": "Русское название",
  "nameEn": "English name",
  "aliases": ["другое название"],
  "muscleGroups": ["Ноги"],
  "exerciseType": "Силовые",
  "thumbnail": "/images/approved-card.webp",
  "instructionImage": "/images/approved-card.webp",
  "imageAlt": "Описание фактического содержимого иллюстрации",
  "status": "verified"
}
```

Используйте существующие значения категорий из `src/data/types.ts`. Одна картинка может использоваться для обоих полей; копировать файл не нужно. Для отдельного превью сохраняйте пропорции и читаемость. Компоненты менять не требуется.

ID постоянный и не зависит от названия. Slug уникален и определяет публичный URL. Не меняйте его без миграции ссылок. Упражнения со схожими именами могут иметь разные ID. Ручное объединение требует проверки техники, обновления всех ссылок в тренировках и сохранения каждого отдельного вхождения.

## Неуверенная идентификация

Для неподтверждённой записи используйте `"status": "needs-review"` и обязательное `"reviewNote": "Что именно требует проверки"`. По умолчанию карточка инструкций такой записи **не показывается**. Для уже идентифицированной по предоставленному пакету AI-иллюстрации можно явно добавить `"reviewPreview": true` и `"imageOrigin": "ai-generated-illustration"`: тогда только после замечаний доступен сворачиваемый просмотр черновика. Это не подтверждает технику. Для неуверенно идентифицированного движения оставляйте просмотр отключённым. Замечания перечисляются в `reviewIssues`. Исходный статус пакета можно сохранять в `sourceStatus`. Не изобретайте технику и не выдавайте иллюстрацию за кадр из видео. Поля путей сохраняют структуру схемы, но требуют реальных утверждённых файлов перед выпуском. По возможности не добавляйте такую запись в реальную тренировку до проверки.

## Тренировка

Добавьте запись в `src/data/workouts.json`:

```json
{
  "id": "workout-stable-id",
  "slug": "workout-readable-slug",
  "title": "Название тренировки",
  "source": "Подтверждённый автор",
  "sourceUrl": "https://example.com/source",
  "description": "Краткое описание по проверенному источнику",
  "status": "verified",
  "exercises": [
    { "id": "occurrence-a", "exerciseId": "ex-stable-id", "order": 1 },
    { "id": "occurrence-b", "exerciseId": "ex-stable-id", "order": 2 }
  ]
}
```

Каждое вхождение имеет собственный уникальный внутри тренировки ID. Повтор одного упражнения — новое вхождение с прежним `exerciseId`, а не копия упражнения. `order` — непрерывные целые числа от 1. UI сортирует по ним. Таймкоды и длительности не добавляются.

`coverImage` необязателен: путь к локальному файлу `/images/...`; при отсутствии используется нейтральная декоративная обложка. Демонстрационные данные помещаются **только** в `workouts.fixtures.json`, с `needs-review` и явным пояснением вымышленного порядка. Они не смешиваются с реальным списком тренировок.

## Проверка перед передачей

```sh
npm run validate:content
npm run validate:assets
npm run test:e2e
npm run build
```

Проверьте реальную картинку в каталоге, на странице упражнения и в увеличении, в том числе на узком экране. Сверьте технику, подписи и последовательность с источником вручную: программные тесты не доказывают анатомическую правильность. Новые изображения должны оставаться отдельными файлами, не base64 в JSON.

Валидация проверяет уникальность ID/slug, существование ссылок, категории, локальные пути и порядок. Отдельная команда `validate:assets` проверяет наличие файлов. После импорта HASfit все 13 файлов доступны, и эта проверка должна проходить. Любые ошибки необходимо устранить.


## Предварительная последовательность из внешнего пакета

Для неподтверждённого порядка сохраняйте `"verificationStatus": "sequence-unverified"`, `"status": "needs-review"` и обязательный `reviewNote` с конкретным ограничением. Не меняйте статус на подтверждённый без сверки полного видео. Название интерфейса — по-русски; исходное английское название можно сохранить в `originalTitle`.

## Исторические ID

При **ручном**, документированном сопоставлении точного дубликата прежние ID можно сохранить в `legacyIds`. Используйте `getExerciseById` для разрешения ссылок: он поддерживает канонический и исторические идентификаторы. Валидатор запрещает конфликты между ними. URL определяется slug и не должен меняться при такой миграции. Пример обоснованного сопоставления DB Squat описан в `HASfit_IMPORT.md`.
